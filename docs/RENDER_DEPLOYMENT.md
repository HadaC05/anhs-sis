# First deployment to Render

This repository includes a Render Blueprint in `render.yaml`. It creates a Docker web service and a managed PostgreSQL database. Do not upload or commit `.env`; Render stores the production secrets.

## Before you start

1. Push this project to a private GitHub repository. Confirm that `.env` is not included in the commit.
2. Create a Render account at [render.com](https://render.com) and connect your GitHub account.
3. In Render, select **New > Blueprint**, choose the repository and approve the proposed `anhs-sis` web service and database.

## Set the required environment values

After the Blueprint creates the service, open its **Environment** page. Enter these values before manually deploying:

| Key | Value |
| --- | --- |
| `APP_URL` | Your service URL, such as `https://anhs-sis.onrender.com` |
| `ASSET_URL` | The same URL as `APP_URL` |
| `MAIL_MAILER` | `smtp` when you have email credentials (otherwise leave `log`) |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` | Your email provider's production values |

`APP_KEY` is securely generated by the Blueprint. `DB_URL` is automatically connected to the Render PostgreSQL database. Never paste either secret into Git.

Deploy the service. The startup script runs the Laravel migrations, caches the production configuration, and starts Nginx/PHP on Render's assigned port. Check **Logs** until you see the service become live, then visit `/up` and the homepage.

## Create the initial test accounts

Migrations create tables but do not create application users. To load the included test data, temporarily set `RUN_DATABASE_SEEDER` to `true` on the web service's **Environment** page and deploy once. After the deploy is live, change it back to `false` and deploy again. The seeded administrator signs in at `/login` with username `admin` and password `password`. Change that password before using real data.

## Important: student uploads

By default Render discards files created by the app when it restarts or deploys. This application stores student photos and documents locally, so configure persistent storage before accepting real uploads:

1. On a paid Render web-service plan, add a persistent disk mounted at `/var/data`.
2. Add `PUBLIC_DISK_ROOT=/var/data` and `FILESYSTEM_DISK=public` to the service environment.
3. Redeploy. Existing production uploads need to be copied to the disk separately.

For a longer-term school system, object storage (S3-compatible) is preferable to a disk because it is easier to back up and scale. Do not use the free plan for live student records: it sleeps after inactivity and does not provide persistent disk storage.

## After the first deployment

Create the initial administrator through the application's normal setup path. If you need queued email or background jobs later, add a separate Render Background Worker that runs `php artisan queue:work --tries=3 --timeout=90`, then change `QUEUE_CONNECTION` from `sync` to `database`.
